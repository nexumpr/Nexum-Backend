# RFC-025 — Enmienda contractual aditiva: E002 401 y E005 413

| Campo | Valor |
|---|---|
| Documento | `sdd/_control/H08/RFC-025-ENMIENDA_E002_401_E005_413.md` |
| Versión | 1.0.0 |
| Fecha | 2026-11-24 |
| Estado | **APPROVED** por la autorización `APRUEBO_CORRECCIONES_TRANSVERSALES_CONFIRMADAS_54_ENDPOINTS` (Scrum Master, 2026-11-24) |
| Autoridad | Orden ejecutiva del 2026-11-24, §D3 (E002) y §D3 (E005) |
| Instrumento | Enmienda aditiva del OpenAPI; no altera autenticación, cuerpos ni códigos existentes |

## 1. Problema

La auditoría del 2026-11-24 confirmó dos desajustes entre el runtime y el contrato:

| Operación | Runtime | OpenAPI previo | Riesgo |
|---|---|---|---|
| E002 `POST /api/v1/auth/login` | Devuelve **401** con `ErrorEnvelope` genérico ante credenciales inválidas | No declaraba 401 | El cliente y los tests de contrato no podían validar el caso más común de error |
| E005 `POST /api/v1/auth/password/forgot` | Devuelve **413** `PAYLOAD_TOO_LARGE` si el cuerpo excede 4 096 bytes | No declaraba 413 | Respuesta real fuera de contrato |

## 2. Cambio aplicado

### E002

Se añade la respuesta `401` con `ErrorEnvelope`:

```json
"401": {
  "description": "UNAUTHORIZED - credenciales invalidas (mensaje generico, sin enumeracion).",
  "content": { "application/json": { "schema": { "$ref": "#/components/schemas/ErrorEnvelope" } } }
}
```

No se modifica la respuesta `200`, los códigos existentes, el `security: []`, el flujo de login ni el mensaje genérico. Es **aditivo**.

### E005

Se añade la respuesta `413` con `ErrorEnvelope`:

```json
"413": {
  "description": "PAYLOAD_TOO_LARGE",
  "content": { "application/json": { "schema": { "$ref": "#/components/schemas/ErrorEnvelope" } } }
}
```

El handler ya devuelve `413` con `PAYLOAD_TOO_LARGE` al superar `MaxBytesReader(4096)`. No se cambia el límite, la semántica anti-enumeración ni la respuesta `202`. Es **aditivo**.

## 3. Compatibilidad

- No se elimina ninguna respuesta ni campo.
- No se cambia el esquema de request/response.
- No se altera autenticación, sesiones, tokens ni rate limiting.
- Android no requiere cambios: los códigos añadidos ya podían ocurrir en runtime.
- El comparador de compatibilidad de I-150 debe clasificarlo como compatible (respuesta añadida). Si lo marca como ruptura, se revisará el comparador, no se ocultará el cambio.

## 4. Paridad y validación

- JSON y YAML actualizados con el mismo contenido.
- `validar_h06.py` → `H06_CONTRACT_PASS`.
- `verificar_publicacion_i150.py paridad` → `PARIDAD_OK` (75 operaciones, 55 rutas, 102 esquemas).
- Pruebas HTTP de E002 (401) y E005 (413) existentes o añadidas.

La autorización `APRUEBO_CORRECCIONES_TRANSVERSALES_CONFIRMADAS_54_ENDPOINTS` cubre expresamente “defectos inequívocos de implementación, seguridad, errores HTTP y regresiones reproducibles” y “reconciliar códigos HTTP y OpenAPI mediante la enmienda correspondiente”. **No se ha inventado una firma nueva.**
